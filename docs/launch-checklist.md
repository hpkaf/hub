# 上线清单 · 从本地到「能公开发出去的站」

目标：3 周内有一个**真实、持续更新、能被检索到**的站点，作为"AI 赛事雷达创始人"这个 title 的实证。
不要一次性做全，按下面的顺序，每一步都能独立上线。

---

## 0. 命名与域名（第 1 天，半天）

现用工作名：**AI 赛事雷达 / AI Race Radar**。

| 候选 | 域名 | 说明 |
| --- | --- | --- |
| AI 赛事雷达 | `airaceradar.com` | 直白、中英一致，首选 |
| AI 赛历 | `aisaili.com` | 双拼短、偏日历订阅心智 |
| 赛雷达 | `saileida.com` | 更短，但含义需要解释 |
| HackChina | `hackchina.com` | 偏黑客松，赛道窄但记忆点强 |

查域名：Namecheap / Cloudflare Registrar / 阿里云万网（比价 + 看是否被占）。
买 `.com` 即可（¥70/年）；`.ai` 溢价到 ¥600+/年，**第一年不建议**，等有了订阅量再换。

命名原则：能口头说清、不蹭已有品牌、搜出来第一页是你的站。

---

## 1. 仓库与站点（第 1–2 天）

```bash
cd ai-race-radar
git init && git add -A && git commit -m "feat: AI 赛事雷达 v0.1"
# 在 GitHub 建仓库 ai-race-radar（public，为了免费的 Actions 额度）
git remote add origin git@github.com:<you>/ai-race-radar.git
git push -u origin main
```

- Settings → Pages → Source 选 **GitHub Actions**；
- 首次手动跑一次 `daily-refresh` workflow 验证部署；
- 域名买好后：Pages → Custom domain 填域名，DNS 加 CNAME 指向 `<you>.github.io`；
- 同时设置 Repository 变量 `SITE_URL=https://你的域名`（或改 workflow 里的 env），保证 `sitemap.xml` / `.ics` / 邮件链接是正式域名。

---

## 2. 首屏数据（第 2–3 天，最重要）

站点能不能发，取决于首屏有多少条**真能打开**的赛事。目标 **30–40 条**：

- 人工核验的种子（`data/seeds.yaml`）≥ 25 条，覆盖：天池、讯飞、DataFountain、百度 AI Studio、DoraHacks、活动行、高校/大厂自办赛；
- 抓取补充（`candidates_comp.json` / `candidates_hack.json`）里链接实测 200 的才进站；
- 每条至少要有：标题、主办方、线上/线下、报名截止、官方链接。

验收：在手机上点 10 条，10 条都能打开且信息对得上。做不到就继续补，**别发**。

---

## 3. 订阅（第 3 天，半天）

优先级从低到高：

1. **`.ics` 日历订阅**（已有）：零成本，放进页头和邮件签名；
2. **邮件摘要**（已有脚本）：
   - 免费额度方案：Resend（100 封/天）、Buttondown（100 订阅免费）→ 不用自己维护 SMTP；
   - 自建 SMTP：QQ 邮箱授权码即可，适合 < 50 人；
   - 订阅入口先做成「发邮件到 `subscribe@你的域名`，自动进列表」或一个 Google Form，**不要先写后端**；
3. 退订：每封邮件底部写「回复退订即可」并在 README 记录处理流程。

---

## 4. 收录与 SEO（第 4–7 天，每天 30 分钟）

- 部署后先验四个机器入口：`/llms.txt`、`/api/events.json`、`/sitemap.xml`、`/calendar.ics` 都要 200 且 MIME 正确（json / text/plain / xml / text/calendar）；
- 提交 sitemap：Google Search Console、Bing Webmaster、百度搜索资源平台；
- `llms.txt` 在站内页脚与 about 页已互链，方便 AI 搜索/代理发现；后续可在文章与 GitHub README 引用；
- 页面 title/description 已就绪（每场详情页独立 title）；
- 给 3–5 个相关 GitHub awesome-list 提 PR（awesome-ai-china / awesome-hackathon 等），带链接；
- 在知乎/V2EX 写一篇「我为什么做了一个只收 AI 赛事、每条都核验的清单」——方法本身就是内容。

---

## 5. 推广（第 2 周起，每周 2 次）

按 ROI 排序：

1. **主办方**：把该赛事的详情页链接发给主办方运营（微博/公众号/邮箱），请他们校对并顺手转发——这是最快的冷启动，也是 B 端关系的开始；
2. **高校社群**：AI/计算机学院的竞赛群、实验室群，发"本周 AI 赛事 3 条"；
3. **小红书/即刻**：发「AI 赛事速报」图文卡片（封面用本周 Top3），导流到站；
4. **公众号**：注册「AI 赛事雷达」，每周一篇周报，同步到站；
5. V2EX / 少数派 / 掘金：只发一次，讲方法论不讲广告。

节奏：周一更新一批 + 周四发一次摘要。坚持 4 周再评估。

---

## 6. 指标（每周日看一次）

| 指标 | 目标（第 1 个月） |
| --- | --- |
| 收录赛事（活链） | ≥ 60 |
| 核验覆盖率（verified/总数） | ≥ 95% |
| 邮件/日历订阅 | ≥ 50 |
| 周回访（GitHub Pages 无统计 → 接 Cloudflare/Umami） | ≥ 100 UV |
| 主办方主动投稿/转发 | ≥ 3 次 |

有这三个数，跟别人介绍时就不是"我在做一个小网站"，而是"我维护着一个收录 60+ 场、每周 100+ 人看的 AI 赛事库"。

---

## 7. 风险与处理

- **信息事故**（错误截止日/假链接）：详情页底部留 "纠正" 入口；发现后 24 小时内改并记录；每个详情页都有核验时间戳，这本身就是信任资产。
- **抓取合规**：只抓公开页面、控制频率（脚本已限 0.25s/请求）、不绕过登录墙；被反爬就标"待确认"，不硬来。
- **季节性**：寒暑假/毕业季赛事少，提前准备"常设赛事/长期榜单"（如高校联赛、平台月赛）填充。
- **变现周期**：前 3 个月不谈钱；先有主办方主动找你要曝光，再谈报价（置顶/合集/投稿入口）。

## 8. 成本与时间

| 项 | 成本 | 时间 |
| --- | --- | --- |
| 域名 | ¥70/年 | 0.5 天 |
| 托管 + CI + 邮件 | ¥0（免费额度） | 1 天 |
| 首屏 30–40 条核验 | 约 6–8 小时人工 | 2 天 |
| 每周运营 | 1–2 小时 | 持续 |

首年总成本 < ¥500。真正贵的是每周的核验时间——所以脚本必须替你做完 95%，你只处理"待确认"。
